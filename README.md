# lab3
Домашняя бухгалтерия
Консольное приложение для совместного и личного учёта доходов, расходов и контроля семейного бюджета. Работает на чистом Python 3.10+ без единой внешней зависимости.

Быстрый старт
python3 main.py
При первом запуске программа спросит, заполнить ли базу демонстрационными данными. Полезные ключи:

Ключ	Назначение
--demo	заполнить базу демо-данными перед стартом
--empty	не предлагать демо-данные при пустой базе
--data-dir ПУТЬ	другой каталог с CSV-файлами (по умолчанию ./data)
--today ГГГГ-ММ-ДД	считать сегодняшним днём указанную дату
Запуск тестов:

python3 -m unittest discover -s tests -t .

Модули и классы
Модуль 1. Управление транзакциями — Transaction, TransactionService
Операция хранит сумму, тип (расход/доход), категорию, дату, участника и комментарий. Сумма всегда положительная, знак задаётся типом.

add(...) — создать операцию;
edit(id, **changes) — изменить поля (None означает «оставить как есть»);
delete(id) — удалить;
query(...) — выборка по периоду, категории, участнику, типу и тексту;
find_similar(...) — поиск вероятного двойного ввода;
totals(...) — суммы доходов, расходов и итога.
Модуль 2. Категории и бюджеты — Category, BudgetManager
Категория привязана к типу: категория расходов не примет доходную операцию и наоборот. Лимит задаётся на конкретный месяц.

set_limit(category, month, limit) — поставить или обновить лимит;
remove_limit(...) — снять лимит;
status(category, month) — состояние лимита;
statuses(month) — все лимиты месяца, от большей доли расхода к меньшей;
exceeded(month) / near_limit(month) — превышенные и приближающиеся (≥ 80%);
check(category, month) — готовый вердикт «превышен ли лимит по категории?».
BudgetStatus — неизменяемый снимок: limit, spent, remaining, usage, is_exceeded, is_close, state, плюс bar() для мини-графика.

Модуль 3. Аналитика и отчёты — AnalyticsService, FinancialReport
balance() — общий баланс: стартовый остаток плюс все доходы минус расходы;
income(start, end) / expenses(start, end) — суммы за период;
by_category(...) — разбивка расходов по категориям с долями;
top_categories(..., count=3) — топ-N самых затратных категорий;
monthly(start, end) — сводка по месяцам;
build_report(...), month_report(...), member_report(...) — отчёты.
FinancialReport считает итог, остаток на конец периода, средний расход в день, долю сбережений и умеет сам себя напечатать (render()).

Модуль 4. Хранение данных — DataRepository, FileStorage
Данные лежат в каталоге data/ (путь меняется ключом --data-dir):

Файл	Содержимое
transactions.csv	операции
categories.csv	справочник категорий
budgets.csv	лимиты по месяцам
members.csv	участники семьи
settings.csv	валюта и стартовый баланс
Особенности реализации:

запись атомарная: сначала во временный файл, затем replace — оборванная запись не портит данные;
пишутся только изменённые коллекции;
при чтении проверяется заголовок CSV, а битое значение показывается с номером строки;
чтение происходит один раз при старте, далее всё в памяти;
ссылочная целостность: категория и участник операции должны существовать, а имя приводится к каноническому написанию из справочника.
Решения по реализации
Деньги — Decimal, а не float. Суммы округляются до копеек (ROUND_HALF_UP), поэтому итоги не «плывут» на длинных периодах.
CSV, а не SQLite. Файлы можно открыть и поправить в любом редакторе; для семейного бюджета этого объёма достаточно.
Сумма всегда положительная. Знак определяется полем type, поэтому нельзя случайно завести расход со знаком минус и испортить баланс.
Совместный учёт. У каждой операции есть участник, отчёты строятся по любому из них, лимиты общие на семью.
Даты и суммы прощают небрежность ввода. Понимаются 1 234,56, 1234.56, 15.10.2026, октябрь 2026, «сегодня» и «вчера».
Ограничения MVP
Нет авторизации: участники выбираются из списка, входов и паролей нет.
Нет валютных курсов и нескольких валют — суммы сравниваются напрямую.
Нет повторяющихся операций и планирования бюджета на будущее.
Одновременная работа двух копий программы не поддерживается: при записи файл заменяется целиком.
